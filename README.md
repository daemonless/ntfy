## Deployment

### Podman Compose

```yaml
services:
  ntfy:
    image: "ghcr.io/daemonless/ntfy:pkg"
    container_name: ntfy
    environment:
      - PUID=1000  # User ID for the application process
      - PGID=1000  # Group ID for the application process
      - TZ=UTC  # Timezone for the container
      # - NTFY_BASE_URL=  # Public URL clients reach the server at; turns on attachments under /config/cache/attachments (or set base-url and attachment-cache-dir in server.yml)
    volumes:
      - "/containers/ntfy:/config"
    ports:
      - "8080:8080"
    # always (not unless-stopped) so FreeBSD's podman rc.d auto-starts it at boot
    restart: always
```

Save as `compose.yaml`, then run `podman-compose up -d`.

### AppJail Director
**.env**:

```
# .env

DIRECTOR_PROJECT=ntfy
PUID=1000
PGID=1000
TZ=UTC
```

**appjail-director.yml**:

```yaml
# appjail-director.yml

options:
  - virtualnet: ':<random> default'
  - nat:
services:
  ntfy:
    name: ntfy
    options:
      - container: 'args:--pull'
      - expose: '8080:8080 proto:tcp'
    oci:
      user: root
      environment:
        - PUID: !ENV '${PUID}'
        - PGID: !ENV '${PGID}'
        - TZ: !ENV '${TZ}'
    volumes:
      - ntfy: /config
volumes:
  ntfy:
    device: '/containers/ntfy'
```

**Makejail**:

```
# Makejail

ARG tag=pkg

OPTION container=boot
OPTION overwrite=force
OPTION from=ghcr.io/daemonless/ntfy:${tag}
```

Save the files above, then run `appjail-director up`.


> [!WARNING]
> Exposing ports in AppJail means that your service can be reached from remote hosts. If that is not your intention, do not expose the ports and communicate with the service using the jail's IPv4 address or hostname assigned by the virtual network.
>
> To avoid exposing ports, just remove the `expose` option in your `appjail-director.yml` or from your command-line arguments.

### Bastille

> [!WARNING]
> Bastille's OCI support is **experimental**. It requires `buildah` and shares the host network stack (`inherit`). Mount volumes with `--volume HOST JAIL`; without it, image-declared volumes are stored under `${bastille_volumesdir}/${jail}`.

```yaml
services:
  ntfy:
    name: ntfy
    image: "ghcr.io/daemonless/ntfy:pkg"
    network:
      - mode: host
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=UTC
    volumes:
      - "/containers/ntfy:/config"
```

Save as `bastille-compose.yml`, then run `bastille up`.
Open `http://<server>:8080` from another machine (the server's own browser can't use a published port).
